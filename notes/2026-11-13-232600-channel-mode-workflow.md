# Channel 模式解决不了工作流

昨天晚上我试用了一下，用 Grok 创建了几个不同角色的 Bot，让它们在一个 channel 里分工协作。结果证明 channel 模式还是不行，最终还是混乱的。

我最早在今年 3 月还是 4 月就尝试过 channel 模式。当时 Anthropic 的 Teams 还没发布，我已经构思并试过这个模式。其实那时候就发现了问题：它会引入好几个 Agent 在一个 channel 里互相聊天、互相唤醒。Channel 只解决了一个通信问题，其他问题没有解决，比如软件工程里的效率问题，也就是工作流问题。

一个指令发出去，所有 Agent 都会响应，但它们之间没有协作范式：什么事情该由谁做，完全由每个 Agent 各自的 prompt 决定。于是很容易出现同一件事几个 unit 一起做。靠角色设定，实际上没有办法有效设计工作流。

工作流除了角色，还要设计信息的流向与流动。

所以我的判断是，群 bot 这种模式最终还是会被淘汰；或者说，它最终会退化成一个入口，就像现在 IDE 类工具一样，变成一个 Agent 的沟通入口。背后还是需要一个可靠的 Agent 分工协作模式，去稳固开发工作流。
