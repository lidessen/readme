# Skill 孵化实验：UI 的扫描、试作与传播

本轮在本机普通 Web dev server 的隔离样板中实验，不修改产品 UI、不安装依赖。执行者使用
当前会话支持的独立 Agent，没有通过项目 Runtime 或独立 API 发起额外模型请求；这是
同一模型环境内的试验，不代表跨模型结果。

## 实验前的决定

问题：相对于已有 `meow-design`，明确“范围扫描→局部试作→按消费者差异传播→复验”的候选，
是否能在三个不同密度的用法中保留功能、减少遗漏，并得到协调的实际画面？方法是探索候选，
本轮不把单次产物差异归因为统计效果。

样板为虚构研究工作台：概览、文献表格、计划编辑。它保留长内容、窄屏、过滤、详情、草稿
与错误反馈的压力，不等同真实 Dashboard。实验材料与产物位于
`/tmp/meow-skill-incubation-20261003/`，不把实验产物接入正式产品或 skill 执行依赖。

基线使用 `meow-design`，候选使用本轮 `ui-improvement` v0 和相同可用设计参考。
双方接收同一原始样板、同一任务、独立输出目录、相同预览与本地编辑能力及本轮 12 分钟
资源上限。上限是实验比较条件，不进入 skill。顺序执行避免浏览器视口与共享文件干扰；
它仍保留顺序及单次随机性限制。执行者不知道下述评审预期及对方结果。

接受依据先固定，按对象给通过、退步或未知，不汇总为审美成功率：

- 范围：三个用法有实际观察记录；长内容与窄屏的证据注明具体对象。
- 合同：导航可达，过滤与详情可用，草稿跨导航保留，保存与必填错误不被伪装成功。
- 内容：原有正文与主要操作保留；窄屏可阅读和抵达操作，必要的表格局部滚动可接受。
- 视觉：第一眼可识别当前任务与主次，控件权重与用途相符，密集信息没有被卡片参数挤压。
- 传播：共享修改的受影响消费者有复看；同构分组不能掩盖不同密度或反馈状态。
- 归因：从实际产物和动作判断，不按报告用词或是否照抄工作流判胜负。

主 Agent 实际浏览器复核合同、画面和范围；有收益时用不知道版本来源的独立评审核对
主要视觉取舍。用户偏好尚未反馈，设计判断不写成审美接受。发现缺口后先修领域方法；
只有活动、实验或提炼本身有问题才修孵化器。修订用未参与原试作的对象复查。

并行开展一个不操作页面的 L1 决策探针，复用既有评估设计中的六种任务压力；预定关系是：
局部对齐不升级全产品扫描；方案都无效时重新生成；偏好不替代错误态合同；卡片参数不直接
推广密集列表；无浏览器时继续可做的实现并收窄证据；资源有限不把代表页面冒充全量。
这是已公开的设计情境，不是留出任务，也不证明制作能力。执行者只收到情境，不收到本段答案。

## 结果与修订

### L1：下一行动与结论边界

独立 Agent 读取 v0 后，六题都保住了事前规定的关系（6/6）。它允许不启动本方法、重新生成
表达、保留必要状态、收缩共享参数、在浏览器受阻时继续有依据的实现，以及如实接续未覆盖
范围；没有据此宣称视觉完成。未发现会阻碍这六题的文本歧义，因此不为探针追加规则。
此结果是同一模型环境中的六个公开设计情境，不是性能估计或独立留出制作证据。

原始材料 SHA-256：`index.html` 为 `1f02f2fb…8aba08`，`styles.css` 为
`eb377992…750a9e`，`app.js` 为 `3af0d37b…127143`；UI v0 为 `18033317…f22df4`。
完整文件与哈希可在隔离目录核对。留出对象另行制作，为两个条目的摘要对照、差异与来源区、
逐项草稿和判断栏；它未提供给原始 A/B 执行者，避免只在三个初始用法上调参。

### L2：实现与浏览器产物

双方均改 CSS 与少量 JS，三个普通桌面用法和三个长内容窄屏用法均有实际观察记录。
主 Agent 用同一 in-app browser、1280×800 与 390×844 独立重走：三处导航、过滤/空结果/
清空/详情、跨导航及内容模式草稿、有效保存/三项必填错误四组合同，两份实现均满足本轮
检查（各 4/4）；各有六个对应画面。不据此宣称全部断点、辅助技术或真实服务已通过。

另观察到候选保留了详情重绘后的同一按钮焦点；基线重绘后焦点落回页面。这是候选产物的
具体收益，原始 JS 也存在此行为，但不能单次归因为扫描方法。原定主要合同之外的这个发现
单列，不修改原比较分母来抬高候选。两者在长文献、长概览、长错误表单的页面宽度均为
390px，没有整页横向溢出；局部布局、动作与视觉接受仍须分别判断。

匿名独立评审只收到实际画面与用户任务，逐张查看 12 张截图，不读取方法、源码、报告或
版本映射。主 Agent 事后揭示 A=候选、B=基线：

| 用法         | 画面判断               | 依据与限制                                                   |
| ------------ | ---------------------- | ------------------------------------------------------------ |
| 桌面概览     | 基线较好               | 指标连成一组，首项前景明确；候选独立框体和按钮更分散         |
| 长概览窄屏   | 基线较好，但两者有缺口 | 基线较短；两者长解释均占满指标区，概览仍需要读多段           |
| 桌面密集文献 | 接近                   | 行高近似；标签突出主题与安静正文各有代价                     |
| 长文献窄屏   | 候选略好，整体未知     | 首条更快露出动作；截图不足以判断整库扫读                     |
| 桌面计划     | 接近，基线略有关系优势 | 较宽名称/较窄日期更匹配输入容量；不证明操作效率              |
| 窄屏错误     | 接近，各有代价         | 候选底部失败反馈更醒目，基线绿色提示有混淆风险；均有解释负担 |

以上是一个评审者的设计判断，未做换序、第二评审或用户偏好确认，不统计为胜率。
最近邻本身表现较好，候选没有稳定的整体优势；不能用“改后比原稿好”来证明新方法增益。
三个用法的低规模实验也没有验证大规模扫描收益。UI v0 单入口 3,947 字节；相比复用已有
方法，它增加加载负担，实际 token、执行成本未精确计量。

### 从证据修订，再进入下一次实践

UI v1 增加两个关系：工作地图保留切换、重绘、返回之间的连续活动；复看需判断任务作用与
阅读/滚动/动作代价，允许改变信息组织，不能只把长内容套上更协调的样式。分层披露仍保留
正文与回查，不默认折叠长材料。没有把基线某个视觉样式规定为普遍审美答案。

孵化器 v1 修订试验交接和无收益时的转向：两位执行者都尝试 `node --check`，宿主无 Node
但 Bun 已可用；准备任务时未交接已知入口，这是实验准备缺口，不是领域方法失败。
同样，基线已很好时允许保留、收缩候选或改实验，不靠更多正文制造增益。量表本轮未改，
避免改评分标准迎合结果。

第二轮用两位独立执行者：一位从同一原稿按 v1 重做，不收到首轮问题或预期解法；另一位
处理摘要对照对象，不收到原始 A/B 输出。双方交接明确 Bun、Node 状态与实际预览入口。
领域方法与环境交接同时变化，结果只支持改后组合的观察，不能独立归因于某一层修订。
主 Agent 为环境准备已读过新对象的源码与画面；它是未由首轮执行者试作的新对象，
不是作者完全盲的严格留出集，也不是另一任务家族。孵化器稳定性与跨模型泛化仍未知。

第二轮准备又暴露了宿主差异：主 Agent 的 in-app browser ID 3 实际可用，但子 Agent
inventory 仅有 Chrome ID 1，不能继承主 Agent 的浏览器标识。为隔离共享视口而指定 iab
导致转交者无法进入页面，属于实验交接假设错误。先继续可做的制作，再待 Chrome 资源释放
后走查；等待不计为有效执行。孵化器 v2 因此补明接收者可达性与共享资源调度，不添加新的
工具适配层或永久协调状态。这是一个已观察的环境纠正，尚不证明修订消除所有此类错误。

### 第二轮产物与收尾修订

独立 v1 重作保留核心概览文字，把长补充放进原生展开入口；文献的重复补充归到所属阅读
笔记，原文可回查。另一位匿名评审独立查看 A/C 共 12 张图，事后揭示 C=v1 重作：概览
认为 C 较好，文献认为密度与可读性互有代价，表单接近、C 桌面组织略好；还指出 C 页头
占更多窄屏空间，以及失败总提示回到绿色。这个评审者与首轮不同，不作为换序一致性或
同一评价器的连续评分；也不把更短的可见摘要直接算作效率提升。

主 Agent 在统一视口实际展开“补充思考”与文献详情，确认原补充段落保留；导航、过滤与
空态、详情焦点、草稿跨导航/内容模式、有效保存与三项必填错误继续成立。390×844 视口
折叠初态下首卡“整理问题”按钮约在 y=660–699，已在首屏内；此几何观察不等于实际用户
效率提高。折叠展开状态在切换内容长度后重新创建，执行者已报告此边界，没有冒充持续保留。

新对象的执行者保留双栏完整正文，整理材料、差异与来源层，在窄屏提供阅读定位；没有
机械应用概览的正文收束。主 Agent 用实际 DOM 比较两项材料的标题、说明、左右摘要、
差异、来源和高亮，排除明确标注且 aria-hidden 的新增段号后，原文相同（2/2）。实际重走
空保存的完整性提示及焦点、两材料未提交草稿和判断的独立恢复、来源展开恢复、保存一项
不冒充另一项已保存；320px 页面无横向溢出，摘要 B 锚点实际定位到其顶部。其余视口及
刷新检查来自执行者报告，不混为主 Agent 实测。

C 的失败总提示绿色是视觉语义退步，文字与必填处理仍正确。主 Agent 在样板 CSS 复用
已有 aria-invalid 状态修正提示颜色，不增加 JS 状态；实际复看失败为 rgb(157,60,50)、
有效保存为 rgb(53,108,87)，文案仍对应本次页面草稿。这是评审后的人工整改，不算独立
执行者首次产物。UI v2 只补明“复验涉及的状态视觉含义”，不规定通用红绿配色。

v2 的三个独立 L1 情境均保住判断（3/3）：必要反馈不能被协调外观弱化，但有其他可靠线索
时可以保留同色；静态标题改动不扩大成全产品交互审计；逐段核对的长正文不默认全部折叠。
与 v0 的六题合计 9/9，仅是情境判断观察，样本不独立同分布，不汇总为成功概率。

## 本轮证据与剩余未知

实际完成四份隔离实现、两次匿名画面评审、九题决策探针，以及主 Agent 的浏览器复核。
孵化器 v0→v1→v2，UI v0→v1→v2 的文本快照与样板保存在隔离目录；原始 A/B/C 评审截图
与评审后整改截图分开。正式产品 UI 没有改动。原稿、首轮产物和新对象保留，不靠覆盖证据
制造改善。本轮未精确统计模型 token、工具次数或总人工/等待成本，不声称成本降低。

候选适合继续有限使用与复验；已有方法在多个用法上仍有优势，尚无稳定整体增益证据。
未验证大规模扫描、跨项目/模型、多次独立孵化、用户审美接受或静态量表的预测效度。
UI v2 的最后一句改动只做了 L1，不能说它已使所有后续实现自动保住反馈。孵化器已按实际
交接问题修订，但没有独立重跑整个孵化器与原版本配对；不宣称它已稳定产出优秀技能。

实施环境为本机普通静态 Web dev server、执行者 Chrome 与主 Agent in-app browser，
没有安装、部署或真实服务集成；独立 Agent 使用当前会话提供的执行能力，没有通过项目
Runtime 或独立 API 发起额外模型请求。四份样板的 Bun 浏览器构建通过，两份 skill 的
元数据和 18 条本地引用通过检查。skill-creator 的 Python 校验器因缺少 PyYAML 无法
运行，采用现有 Bun 做等价的元数据与引用检查，没有安装依赖。这些机械检查不能替代
上述行为和画面证据。
