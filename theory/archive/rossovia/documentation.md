# 文档归属与变更收口

状态：当前开发维护约定。本文承接[文档入口](../README.md)的状态页内、一文一家、记录只增不改三条规则；角色执行入口为[文档书记员](../../.agents/skills/documentation-clerk/SKILL.md)。通用职责与交接见[项目协作](collaboration.md)，本文只持有文档归属和收口规则。

## 先判断文档的地位

目录、标题中的“设计”和最近修改日期都不能单独证明文档是当前权威。正文开头应说明地位、适用边界和必要的基准或替代链接；实现程度另据源码与验证说明。

| 地位                 | 持有什么                                       | 归位与阅读方式                                                                      |
| -------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| 当前合同或已采纳目标 | 已确认的职责、行为和边界；目标未落地处明确注明 | 通常归 `architecture/<域>/`；已有稳定目标页可保留原路径，由域入口明确指向           |
| 候选设计或研究       | 尚待裁决的方案、反例与探索                     | 指向当前合同基准，说明本次想改变什么；不能把候选 Schema、模拟结果或新日期当采纳证明 |
| 执行计划             | 工作包、依赖、剩余项、验收条件和证据入口       | 归 `plans/`；引用合同，不另写一套产品行为；目标已变时清理旧行动依据                 |
| 验证方法             | 操作步骤、场景和如何取得证据                   | 归 `testing/` 或对应技能；方法存在不表示检查通过                                    |
| 历史与现场证据       | 某轮当时的输入、决定、观察和限制               | 归 `records/`；新结论另记，原正文不回写；只有已采纳并回填合同的决定才能指导后续实施 |

入口 README 只负责导航与阅读触发，状态放在负责页面；不要在多个索引复制完成百分比、实现状态和待办。模块 README 持有本模块使用合同，跨模块边界由对应合同页持有，二者以链接接合。

## 同一边界只留一个当前合同 owner

变更前从入口确定哪个页面持有这次行为裁决，其他页面只写其所属边界或引用。不另建权威注册表；在原页面和原入口中把关系讲清即可。

候选必须链接所基于的当前合同，已采纳的决定回填该合同；执行计划随后更新剩余项，现场记录保存证据。尚有争议的决定列为未决，不借格式整理作架构裁决。实现与合同冲突时按证据报告缺口，不把源码偶然行为升级成目标，也不把目标写成已实现。

取代一份设计时，新页面说明取代的边界并链接旧页面，旧页面开头链接新 owner。旧文仍有独立有效部分时注明保留范围；没有当前用途的旧目标退出当前导航，只在明确的历史来源入口保留。历史记录正文不改，当前入口补导航即可。无需为了建立替代关系批量移动旧文件。

## 一次变更怎样关闭文档工作

1. 明确受影响合同、计划、消费者说明和入口的文件 owner；只处理本次边界。
2. 据已采纳决定更新合同，分别写清目标、现状及未决事项；实施或检查回执按其实际证据更新原计划或单轮记录，不能将测试绿色扩写为产品全面完成。
3. 同步引用方和被取代页面的开头关系，移除会继续指导旧行为的当前导航。正文引用原 owner，不再复制同一裁决或剩余清单。
4. 检查修改页的链接、状态与格式，确认历史正文、无关 diff 和未经采纳的方案未被改写；交付时返回变更页、当前 owner、证据、未决项和未覆盖范围。

## 独立书记员的长期职责

跨模块长任务或涉及合同／文档权威变更时，主 agent 开始即指定一个独立子 agent 为书记员，并给出明确文档文件所有权。产品合同由设计负责人裁决，技术证据由实现和验收负责人提供；书记员不重跑技术测试或重新审查全部源码。小笔误和单页局部修正可直接改，不必启动整个角色流程。

过程中，主 agent 将已采纳决定与实现验收回执交给书记员。实现者说明需要同步的合同和证据，避免各写一份重复总结；跨边界文档由书记员统一回填，模块本身的局部使用说明可保留原实现者 ownership。同一文件同一时段只给一个编辑 owner，需要移交时先由主 agent 协调。

书记员可整理入口、状态、候选基准、替代关系、记录归位和据证回填，不能自行决定产品架构、清空运行数据或宣布未验证的完成。冲突以准确页面、段落和证据报主 agent 裁决；同时继续归位无争议材料，不让局部争议阻塞全部文档工作。

收口返回简短 `docstatus`：本轮已同步的页、当前合同 owner、仍待裁决或缺证据的项、检查结果。续接可在项目临时记录保存阅读边界和待办，但实施进度仍只归原计划，现场证据仍只归原单轮记录；不建立第二套状态权威。
