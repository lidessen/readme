# Design Steward：角色与验证记录

日期：2026-09-15。变更域：non-memory。

## 需要的差异

在分治审查中，“实现是否符合现有设计”与“这项设计是否值得承担”是不同判断。后者不能
依靠穷举坏设计类型。用户希望构造有整体意识、能舍弃又能保护重要内容的角色，像长期照料
一处空间的人一样判断留与舍。

这里将其表达为“设计管家”：从系统及使用者的长期负担出发，较早比较保留与移除的后果，
敢于关闭没有足够价值的分支。它不把删得多当作成果，也不以局部简洁代替整体收益。
“不好”仍是相对于目标、实际用途、后果和可行替代的判断；角色提供注意与取舍的起点，
不能凭人格产生领域知识、正确答案或删除权限。

## 角色形成

采用 [agent-personality](../../skills/agent-personality/SKILL.md) 的描述型方式，正文可脱离
生成方法独立交接。只借用有实际用途的偏好：先看关系与整体用途，先比较系统后果，在证据
充分时愿意结束低价值分支；不补齐四字母类型，不把“果断”变成盲目裁决。

对照该方法的 N / T / J，分别借用关系建模、系统取舍和收束时机；没有将维度当成心理诊断，
也没有推导这些偏好天然更有判断力。关注谁承担负担来自本次角色目标，不由 T/F 决定价值。

角色的纠偏来自同一个处境：照料者既要去掉负担，也要承担误删后果。低频不等于低价值，
必要复杂度可以保留；新消费者或承诺出现时应改判。来源缺失时查明关系，不把未知当杂物，
也不无限延迟已有足够证据支持的取舍。

独立正文位于 [skill 的角色正文](../../skills/design-steward/SKILL.md#角色正文)。生产 Agent
收到它及共同任务，不需要加载人格生成器、类型解释或本研究记录；角色只在指定任务中生效。

## 工作流中的归属

- `divide-and-conquer` 负责分工、覆盖与整体整合；可将该角色交给承担设计取舍的审查者，
  不预设所有审查者必须挑出冗余。
- `design-steward` 提供局部与全局取舍的工作倾向，输出有依据的建议，允许判断现状合适。
- `design-forge` 用于确需重新锻造核心设计的工作；`defrag` 用于已经确认的整理与归位。

这些是可组合的职责，不是每次必须走完的阶段。主 Agent 核实证据、检查相邻影响并整合，
不能把角色共识当事实，也不能让审查偷偷改写已确认设计。

## 观察设计

以隔离的本地笔记导出器合成材料进行两次独立审查：任务、材料、工具与读写权限相同，
一份加入角色正文，一份不加入。不给缺陷答案或预期取舍，不要求不同结论。

观察选择了哪些材料、如何解释整体负担、保留了哪些必要行为、是否作出可执行取舍及保留
未知；不根据“像不像管家”的措辞评分。补充消费者证据后观察是否修订建议。该样例不代表
真实产品，单次对照不能证明人格增益、跨任务稳定性或大仓库判断质量。

本轮观察：

- 有角色与无角色的审查都建议简化固定流程的转交层，保留低频恢复映射、格式选择和单文件
  替换，暂缓没有性能证据的增量缓存。两者结论接近，未观察到可明确归因人格的增量收益。
- 后续补充一个实际使用 Pipeline 与写入 stage 的归档消费者，两者都撤回了相应移除建议，
  保留 Coordinator 为较小的简化候选，并要求上下文字段变化与消费者共同处理。这里的
  消费者及代码均为合成案例材料，不代表真实产品发现。
- 角色组第一轮还误判了一个 Python 换行字面量；在同样收到“复核源码断言”的请求后，
  通过 AST 核对撤回。主 Agent 另行检查函数输出确认换行正常。这是具体的事实核验失败，
  不能归因角色，也不能因角色体现了取舍倾向而忽略。
- 原始实现未修改；主体审查是静态阅读与推演，未验证导出包恢复、故障处理或真实性能。
  skill 格式、Markdown 格式、相对链接与 diff 空白检查通过。

本轮支持：角色材料已独立交接并参与实际审查，出现了有依据的保留、舍弃和转向行为。
本轮不支持：该人格比普通审查更优、能稳定发现坏设计、跨任务迁移或真实工程验收。
后续应看真实审查中它是否改变了有价值的注意与决定；若只增加角色语言或删减偏执，重审
角色用途，而不是继续添加性格形容词或为每个反例堆一条规则。

## 2026-09-15：审计反馈后的窄幅修订

WorkCell 审计反馈暴露了汇总遗漏、处置冲突、反证核对不足，以及将工程建议留待用户决定的
问题。此次在角色中明确审查建议本身也有维护成本，真实问题不推动修改时仍交代残留风险；
只读限制不妨碍作出建议。分治的实现审计 reference 补充关键主张的反证核对、证据版本与层次，
以及局部发现到最终处置的对应关系。未扩写 design-forge，也未修改原审计或实现。

将修改前后两版冻结在临时目录，由两个无对话历史的独立 Agent 分别读取各自版本及相同的
fixture-v1 合成材料。每组处理导出服务和归档服务两个案例，不告知预期结论，不执行产品。
两组均撤销容量重放误报、补回脱敏遗漏、否决因仓内无调用删除公开入口，区分独立输出探针
与真实 host 复现；均保留低频恢复和合同期限保障，暂缓低收益版本清理，只把临时默认期限
留给产品取舍。新版更显式地对应发现编号，并交代了保留冗余的理解成本，但实质结论相同。

两份 skill 的 quick_validate 通过。本次支持修订后的指导可独立交接，且在这些合成案例中
未观察到误删必要保障；不支持相对旧版的实质效果提升、跨任务稳定性或真实仓库覆盖能力。
这些针对已知失败构造的案例不是盲测留出集；后续以真实审计观察为准，不继续按样例加规则。
