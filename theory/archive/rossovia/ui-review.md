# UI Review

本项目内部开发技能。以实际控件及其使用情境为检查对象，判断设计是否符合预期、实现是否还原设计。
用户要求审查时交付发现；要求整理或修复时继续修改并复验。创建本技能不等于启动 UI 整理。
系统整理配合 [project-sweep](../project-sweep/SKILL.md)，本技能提供 UI 专项检查方法。

## 先确定依据

按涉及范围读取模块 README、局部 AGENTS 和最近的实现；不要把历史样板或候选设计当作已定标准。

- 共享组件以 [MeowUI 开发约定](https://github.com/lidessen/meowland/blob/main/packages/meowtail/AGENTS.md)、[组件与主题合同](https://github.com/lidessen/meowland/blob/main/packages/meowtail/README.md)、实际 `src/theme/` 为依据。
- 应用布局与主题以各应用自己的 README 和实现为依据。例如 [Dashboard](../../../apps/meowland/web/README.md) 的工作区主题不等于 Blog 或 Meowbook 的主题。
- MeowUI 与 Meowland 的共同设计依据见 [项目设计规范](../../../docs/architecture/ui/meowland-ui-design.md)；从任务核对形式、层次、尺度、表面与状态，原型业务对象不作为实现合同。
- 比例、构图、视觉层级与交互质感使用 [interface-design](../interface-design/SKILL.md) 的判断方法；设计或打磨 Meowland 界面时，另读[项目适配说明](../../../docs/architecture/ui/interface-design-context.md)，以当前正式 UI 设计规范为准，历史配方与核对记录不覆盖现行合同。不另建一份字号、色板或审美评分规范。
- 展示与启动入口见 [产品 Workshop](../../../docs/architecture/ui/ui-workshop.md)。它使用已安装的 Meowbook，产品场景留在产品目录；通用组件场景由独立 [Meowland showcase](https://github.com/lidessen/meowland/tree/main/apps/showcase) 维护。

## 默认先做视觉走查

先确认本次设计依据，实际打开对应原型或参考图，再打开实现；没有具体原型的组件，从共同设计规范
推导它应有的任务层次、尺度、表面和状态。依据是目标设计，当前源码与 token 只解释实际效果，不能反过来证明设计正确。

把依据带进这一次判断：用简短说明明确用户在此要读什么、比较什么、操作什么，以及实际启用、
只读、禁用或等待的状态；关联当前文字规范与参考图。来源是实际场景、产品合同和用户要求，
未知处保留未知，不替产品编意图。例如“这几项供横向比较”“不可修改但需要核对当前值”，
分别改变对齐和可读性的判断，单说“检查是否精致”不足以替代这些依据。
委派或独立复核时传递同一份用途、状态、规范和原图；只转发截图会丢失判断依据。
不要把疑似缺陷、修复方案或旧评审结论当成盲评的题设，也不需另建一套文档或状态协议。

以当前任务的完整活动片段为判断单位：先看整屏的主次、阅读轴、区域比例与累计留白，再定位到
组件的轮廓、字体、对齐、表面、颜色和图标。局部修复只需包含受影响的邻接关系；系统走查必须有
代表性完整场景，不能由组件目录照片推导整页还原。明暗、窄屏、长内容和展开状态按影响补查。
原型与实现内容不同，比较设计关系，不要求复制原型业务或做无意义的逐像素匹配。
每条偏差必须说明“预期是什么、实拍是什么、为何影响设计目标”，附对应参考与实拍；区分明确偏差、
审美建议和缺少依据的待确认项。截图数量、渲染成功、使用了 token 都不能作为还原度结论。

定稿前回到原图复核发现：可见事实是否成立，引用规则是否适用于这个对象，影响是已经看到还是
仅为风险。规范配色差异不自动等于任务受阻；字体外观不等于已确认 font-family；基础正文字号
不自动排除代码、注释等专用尺度。相反，“可能是有意的”也不能消除已看到的核对困难。
系统走查或存在争议时可用独立视角做此复核，按画面和适用依据裁决，不按票数或问题数量。
审美建议保留具体关系与最小试作方向：例如同类动作共享基线如何改善比较；没有溢出不代表
构图已经成立。改变布局后重新拍照比较，建议本身不能证明修改后更好。

上述输入补全在[方法试验](../../../docs/records/2026-10-10-ui-review-method-experiments.md)中减少了部分漏检；
不是完整审美能力的验收。方法评估才使用匿名样本与漏检记录，普通走查不附加评分或固定 Agent 数量。

### 建立可比场景

复用实际公共组件和已存在的组合入口，核对必要容器、内容区域及滚动归属已接线。用相同视口、
实际主题和相近内容密度并排查看参考与实现；参考只涵盖局部时，保留它在原页面中的位置。
固定高度、画布 padding、空白占位或缺失内容会改变构图，应先确认差异属于场景还是组件。
没有对应原型的新组件，从共同规范推导关系，放进真实使用片段与相邻控件比较。

先修最影响整体的一处关系，再复看原画面。需要试作时可临时调整浏览器样式或比较少量变体；
最终改动回到结构、主题或宿主 owner，重新加载源码拍照。临时覆盖和一次实例变好不能证明共享修复。
保留参考来源、源码状态、story/用法、状态及环境；现有报告和记录能表达时，不另建同步协议或评分系统。

对齐要落到用户实际读取的部位：同一回答的正文起点、同类字段的标题和值、展开内容与所属标题。
先判断外框与可用区域的关系，再用对应 content/body/title 等 part 核对内部阅读轴；外框中心相同，
不能证明正文对齐。连续信息还要看身份标签、分隔与留白是否把同一组拆成重复区块。
缺少用途依据时保留建议；已有可见问题则定位到具体层级，不用“整体未居中”概括内部偏差。

UI 走查默认不运行单元测试、类型检查或扩大为实现审计。浏览器交互用于呈现需要观察的视觉状态；
源码只在解释已经看到的偏差时追踪。用户要求行为审查、组件整理或修复后，才按受影响范围使用下面的专项检查。
Meowbook 启动与 capture 内置的构建检查属于取证接线；失败先修工具或使用获准替代入口，成功不算视觉验收。

## 从画面定位偏差

从实际入口确认控件服务什么动作、处于什么状态，再追到组件和样式来源。
明确要求行为审查、公共组件整理或开始整改时，按需读[实现与归属检查](references/implementation-review.md)；
纯视觉走查不加载它。

### 样式与设计标准

组件负责结构、语义状态与 part；标准主题负责通用视觉；应用负责业务布局及已确认的主题覆盖。
核对实际渲染 runtime 同时安装了组件与主题，默认效果无需 story-only CSS 或某个页面的补丁才能成立。

检查字号层级、控件比例、图标、语义色、焦点、间距、表面与动态是否沿用当前主题关系。
看父子 padding、gap、margin 的累计效果，以及长内容、窄屏和实际组合；使用 token 不自动等于协调。
硬编码、覆盖和局部例外是调查线索，不自动判错；只有它造成尺度漂移、职责错位或实际效果问题才整改。
保留有依据的产品差异，不把 Dashboard、Blog 和展板强制改成同一种外观。

### 实际效果与使用路径

打开与本次源码一致的真实页面，覆盖按受影响关系选择。单个图标修复核对所在控件、相关主题和可见
状态；组件尺度或结构变更再与 Button/Input/Field 等邻接控件同屏比较，到受影响消费者核对组合。
系统走查中每个不同控件用法都需交代；同构列表项可合并记录，但长内容、
错误、禁用等差异不能被默认项代表。场景缺失要记录并按需补齐，不能因此跳过控件。

先核对场景是否真的进入目标用法：比较生产入口与场景传入的 props、默认值、运行时配置和事件接线。
场景标题、`covers` 声明或调用了同名函数，都不能证明走了同一分支。缺失的可独立渲染路径可在授权
范围内用临时预览补查；只审查时不因此修改生产代码。临时场景的结果仍不能替代完整产品接线验证。
区分组件自身行为与场景 `setup`、模拟反馈或样式补丁提供的行为；例如场景设置原生 reset 初值，
只能证明这套组装的重置。声明与实测不符时先收窄证据、补齐场景，不直接认定组件功能有缺陷。

系统走查至少查看桌面、窄屏和相关主题，实际操作鼠标/键盘及适用反馈；局部整改复查会改变该问题
的环境和状态。按问题检查溢出、截断、对齐、层级、
焦点、滚动、返回与草稿保留；主题切换不能靠重挂载掩盖状态丢失。动画存在不等于动态效果成立。
取证区分稳定画面和过渡过程：元素可见不代表入场动画、主题过渡或定位已完成。判断稳定效果时，
等待相关有限过渡完成并复看；禁用动画的截图只作静态对照，不能证明正常动态没有问题。
自动化超时先核对当前视口、折叠入口、弹层与 frame，按真实用户路径重试；不能用强制点击跳过可达性，
也不能把一次选择器失败直接记为产品缺陷。保留失败原因，并继续不受影响的检查。
静态场景证明组件状态，真实产品入口证明接线；mock、截图、DOM 检查与自动化测试分别说明证据范围。
浏览器或必要环境不可用时保留“待走查/受阻”，不得用源码推断视觉通过。
记录阻塞的是哪种能力，并核对环境内获准的替代入口；遵守工具的使用约束，不能通过换工具绕过限制。
场景可运行而产品服务不可用时，继续组件走查，把产品接线单独留待验证；不要把局部阻塞扩成整块停工。

## 用 Meowbook 拍摄走查

组件与场景的静态取证和真实页面批拍均使用 Meowbook CLI；交互路径通过浏览器操作进入目标状态。
开始拍摄前读 [组件拍摄合同](https://github.com/lidessen/meowland/blob/main/packages/meowbook/README.md#组件拍摄)，参数以当前 CLI 为准。
在仓库根目录使用已锁定安装的 `meowbook` CLI；`--no-install` 禁止临时下载。

### 实际 app 与 extension UI

用户要求 app、extension 或全产品走查时，先拍实际运行的页面，不用 Storybook 的 `--all` 代表产品覆盖。
Meowland 的主要路由、设置和只读展开场景在 `apps/meowland/web/capture.config.ts`；扩展视图按真实
启用目录动态发现，项目目录从已注册 workspace 获取，不猜路径或扩展 ID。确认实际服务及源码版本后：

```sh
bunx --no-install meowbook capture --url http://127.0.0.1:3001 \
  --pages apps/meowland/web/capture.config.ts --all --full-page --json
bunx --no-install meowbook capture --url http://127.0.0.1:3001 \
  --pages apps/meowland/web/capture.config.ts --scene settings-appearance --json
```

浏览器入口见 README 的[真实页面批量摄影](https://github.com/lidessen/meowland/blob/main/packages/meowbook/README.md#真实页面批量摄影)。
桌面和窄屏分别批拍，核对页面实际主题；打开离线总览，再逐图检查有意义的场景与扩展局部照片。
没有真实数据的详情不虚构；目录发现失败、就绪失败与真实产品错误分别记录，诊断图不计覆盖。

真实页面保存原视口及可见 iframe 区域，后者裁自原图，保留宿主大小、裁剪与布局。节点是 DOM 区域，
不能称作完整组件树；iframe 的原图已包含真实内容，但顶层 CSS 参照线不穿透其内部。
扩展需通过浏览器 frame API 等待实际控件和加载完成，MessagePort 已连接不代表内容就绪；
SSE、轮询页面不用 networkidle 代替就绪条件。保持正式宿主、CSP 与 sandbox，不另开资产或重组扩展 HTML。
打开表单只观察，不提交；摄影不自动关闭会持久化宿主设置的首启弹窗。浏览器照片不证明原生窗口外框和菜单布局。

### 发现、拍摄与查看

先用目录中的真实 story id 定范围，再选桌面、窄屏和与对象有关的主题，不从标题猜 id：

```sh
bunx --no-install meowbook list --config apps/meowland/web/workshop/dashboard.config.ts --json
bunx --no-install meowbook list --config apps/meowland/web/workshop/dashboard.config.ts --query composer --json
bun run capture:ui --story composer --depth all --out /tmp/meowland-ui-review --json
bun run capture:ui --all --full-page --out /tmp/meowland-ui-review --json
bun run capture:ui --story composer --depth all --viewport 390x844 --dpr 2 --color-scheme dark --out /tmp/meowland-ui-review --json
```

产品场景使用 `apps/meowland/web/workshop/dashboard.config.ts`（`bun run dev:workshop`）。
共享组件使用独立 Meowland 的 showcase，不跨仓 glob 私有 stories，也不在 Rossovia 复制库实现。

大目录先用 `list --query <文字>` 缩小到相关 id、标题、分组或组件，避免完整 JSON 截断后猜入口。
`composer` 是例子，替换为发现结果。先拍整体和组件树，定位后可用 `--select <name>` 聚焦；
它精确匹配实际组件显示名，并保留同名多实例，不是 CSS selector。默认深度为 `1`，首层非透明
组件为 `0`；`--depth all` 用于查看完整局部层级，透明节点仍保留在树中。不要把范围外节点当作漏渲染。
全目录走查才用 `--all`，不要为一个控件重复拍完整目录。没有现成场景时，按 README 的临时
`--component / --export / --props-file` 入口补查；它与 `--story`、`--all` 互斥，源码和 props 路径相对配置 root。

从 CLI 返回的 `directory`、`reportPath`、`manifestPath` 找本次产物，不猜最新目录。
先从离线 `index.html` 的缩略图总览查看批量差异，再打开疑点原图与相关局部 PNG；按场景进入组件树，
`manifest.json` 用于核对来源、环境、替换、节点范围和重跑入口，ARIA snapshot 辅助核对语义。
不能只读 manifest、统计图片数就判定视觉通过。局部图裁自同一张视口原图，应结合整体检查父容器、
邻接关系和遮挡。长页面使用 `--full-page` 补拍整页，整页不替代视口图与局部裁图；内部滚动容器、
懒加载及浮层仍需按用户路径展开或滚动取证。总览缩略图会缩小文字，不能据此直接判断可读性。

读取场景状态和失败信息：`failed`、`unmatched`、`unexecuted` 各有不同含义；批量未匹配的
场景不能记为已覆盖，全批零匹配是失败。失败留下的 `diagnostic` 只帮助定位，不是成功截图。
检查 hidden、offscreen、clipped、近似范围及替换命中，结合预期状态判断，不自动当作缺陷。
实例 ID 仅在本次挂载内有效，前后对照以 story、组件与用法定位，不跨运行硬匹配实例 ID。

内容干扰较大时，用重复的 `--focus '<CSS selector>'` 保留关注对象，其余可观察文字变为浅色条，
保留实际行宽、换行和对齐。先看完整原图，再看聚焦图定位关系，最后回原图核实发现。
优先选包含标签、说明和状态的语义容器；多个清晰区不会自动保留中间区域，参照线也不会扩大清晰区。
报告同时展示原图与聚焦图。处理会人为改变层级，不能据此认定原页面的对比度或审美改善。
命令、边距和产物见 [聚焦素材](https://github.com/lidessen/meowland/blob/main/packages/meowbook/README.md#聚焦素材)。

核对对齐、阅读列或累计内缩时，使用 CLI 的 `--guides`（选中组件）或重复的
`--guide '<CSS selector>'`（精确比较组）生成参照线图与测量 JSON，具体例子见
[对齐参照线与测量素材](https://github.com/lidessen/meowland/blob/main/packages/meowbook/README.md#对齐参照线与测量素材)。
优先选择少量相关目标，保留干净原图；从 `--json` 回执的 `artifacts` 直接取得素材路径。
选择器应对应当前疑问：比较消息和输入框的主区中心时选各自 root；比较连续回复的阅读起点时选
`[data-meowui-part="chat-message/body"]`，展开详情则比较所属 title 与 panel 内实际正文。
用 `--guide-lines bottom` 聚焦同排动作底边，用 `left,right,center-x` 核对阅读列，避免全图线条掩盖内容。
图上编号对应测量目标，边界框和中心的差值不能自动判错，也不能称为文字基线。
向用户展示图片并解释可见关系；批注图是定位证据，不是修复效果图。

### 交互后取证

CLI `capture` 拍摄初始场景；输入、hover、聚焦、展开、滚动或错误反馈后的状态，使用 README
中的 `serve --capture` 与 `meowbook/playwright` 的 `capturePage` 入口。
先核对现有服务是否开启观察且与本次源码一致；需要启动时使用本次独立端口，不重启无关服务。
普通 `serve` 画布未开放摄影接口，不能把能力缺失记成组件失败。

由 Playwright 在 `/canvas.html?story=<id>` 等待 ready；状态标记就绪后会隐藏，应等待属性或
`locator('#story-state[data-status="ready"]').waitFor({ state: 'attached' })`，不能用默认可见等待。
`capturePage` 自己等待场景就绪；操作前仍需等待目标控件。按真实用户路径操作，再在同一个 Page 上
调用 `capturePage`；它保留输入、焦点和环境，不导航或重挂载。记录 `name` 和可复现的
`testLocation`，指向记录操作与前置状态的实际脚本或测试；不为拍摄本身要求新建测试。长页面可传
`fullPage: true`，全页图会直接进入同一 manifest 和报告，不再另写截图文件。
交互照片的复现依据是操作步骤及其前置状态，初始 story 重跑命令不能复现交互结果。
浏览器操作工具没有该 API 时，可使用其普通截图记录交互状态，明确缺少组件树与局部裁图证据。

默认拍摄使用 reduced motion；它支持静态对照，不能证明正常动画或过渡。暗色参数设置浏览器
颜色偏好，不保证场景切换了实际主题；核对画面和主题接线，显式主题控件通过交互切换。
设备预设是模拟，不能写成真机验收。Meowbook 画布照片也不覆盖 gallery 外壳或完整产品服务接线。
Bun 或 Chromium 不可用时按具体缺失能力选择已授权的替代环境；需要 Docker Bun 时读
[docker-bun](../docker-bun/SKILL.md)，不要把基础环境安装隐含成走查必经动作。

修复前后保留同一场景、状态、视口、DPR 与实际主题的可比照片，并重新观察原问题动作。
产物放在临时目录或既有忽略目录，不提交生成图片与原始数据；返回必要的报告与图片路径，
结束时只关闭本次启动的预览。截图生成成功、视觉判断通过、交互通过分别记录。

## 修复与复验

先定位组件、主题还是应用接线负责，再修最小完整边界。公共组件修复后追踪其消费者，复查所有受影响
的不同用法与样式覆盖；不因一处变好就全局标记通过。重新执行原问题动作并观察修改后的实际画面。

实际修改前端代码后，按[执行与证据](../../../docs/maintenance/testing.md#执行与证据)运行 `bun run check`，并按合同风险补相关组件、场景或浏览器测试；纯视觉审查不执行这些检查。
不为纯审美加入硬编码像素断言；格式、类型、测试、实际交互与用户审美接受分别记录。
普通 Web 预览可本机运行；涉及服务集成、安装或部署时按 [runtime-check](../runtime-check/SKILL.md)
核对实际环境。不重启无关服务，不把真实模型调用或发布隐含在 UI 走查中。

## 返回给调用者

纯视觉走查先给设计还原度结论，再列“对象 / 预期 / 实拍差异 / 影响 / 证据”；明确偏差和审美建议分开。
记录实际看过的组件族、主题、视口和展开状态，不把批量拍摄成功写成全部验收通过。
每个发现给出对象与入口、源码/组件归属、预期与实际、影响、修复及复验结果。无问题的对象也保留
简短覆盖记录；相同根因可共用一个问题记录，但受影响入口不能消失。接入 project-sweep 时回写其既有记录，
不再另建状态表。最终说明检查范围、关键改动、浏览器环境、实际通过的检查和未完成的验证。
