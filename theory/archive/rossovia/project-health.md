# Project Health · 项目健康养生

项目内部开发技能。先读[项目健康养生指南](../../../docs/maintenance/README.md)，
按用户本轮目标选规则与方法，不预加载全部指南，也不把维护请求扩展为全仓重构。

## 确定范围并推进

先核对工作树、现有产物和任务涉及的模块。用户指定对象时以该对象为范围；只说“做一次
项目体检”时，先清点当前变更、模块入口和已有检查配置，再明确本轮检查范围与缺口。
查阅规范、检查现状、执行整改分别处理；检查请求不自动授权批量升级或删除代码。
用户已要求整改时持续完成相关修复与验证，不在每个可逆步骤重复确认。

局部组织、清理和告警修复直接按指南中对应规则执行。需要依赖候选查询或升级时加载
[dependency-upgrade](../dependency-upgrade/SKILL.md)；全量或跨模块巡查整改加载
[project-sweep](../project-sweep/SKILL.md)，由其维护分块、根因归并与整体收尾。
多轮验证、真实执行链路或 UI 观察分别按指南选择 test-cycle、runtime-check、ui-review。
复用同一份范围与证据，不再建立一套健康巡查流程或重复任务记录。

## 用证据收口

对发现区分已证实的问题、规范偏离、改进建议与未核实项。按实际 owner 和消费者处理，
目录名、搜索命中和工具告警都需要结合合同判断；不能仅凭 legacy、utils 等名称删除实现。
按受影响风险验证，使用现有命令；`check:all` 不等于全部测试或发行验收。

交付本轮范围、主要发现及处置、执行结果与剩余缺口。小任务在回复中说明即可；跨批次工作
复用已有记录，新增现场记录按指南归位。不为一次检查添加评分、自动化任务或永久扫描器。
