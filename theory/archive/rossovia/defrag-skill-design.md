## 已吸收的初稿评审意见

以下保留研究时的问题与建议表述，其关键判断现已并入正文，不是另一份待执行流程。

### 1. 合并前先区分独立规则和派生视图

初稿提到重复维护，但没有充分解释同一事实可以有多个有效表达。
理论明确：一个语义事实只有一个权威回答，不要求所有内容在一个物理文件。

建议加入：先辨认原始规则、面向不同受众的说明、生成产物和历史记录。
只合并独立竞争的规则来源；对合理视图维护来源及同步关系。
例如 API 参考与入门教程可以并存，不应仅因覆盖同一 API 就合成一篇。

归属判断还应先检查载体用途：已完成计划是否仍在充当现状说明，操作方法是否混在历史日志中？
先选择符合使用关系的载体，再决定目录位置；按项目既有约定处理，不强推统一目录分类。

### 2. 用“删改后会改变什么”检查关键语义

初稿的“保留有效行为”对代码较直观，对文档、prompt 和配置还不够可操作。
根据承重语义原理，逐项变化应核对是否改变对象身份、主张强度、适用范围、来源、优先关系、
允许行动、失败处理或接受标准；只检查与本次对象有关的部分，不变成全量清单。

例如删掉“尚未验证”，可能把目标改成事实；合并两个 prompt 段落，可能改变指令的作用域。
这类修改需要对应的语义验证，格式检查与普通单元测试不一定覆盖。

### 3. 以段落或规则判断存活，不给整份文档贴死标签

一个旧设计可能只有机制被替代，失败原因仍然有效。判断单位应允许小于文件。
确认当前规则由谁维护，再决定保留原记录、抽取独有依据或修正入口；保留明确的被替代关系。
原始记录不可变时，用新说明和索引指向它，不重写历史。

归档后的内容要在需要理由时仍能找到。无需为所有历史自动建摘要、索引或永久台账。

### 4. 把整理的收益与代价说具体

初稿提到理解成本，但缺少选择优先项的方法。
建议按实际负担排序：重复决策、同步维护、寻找规则、跨边界改动，哪一项正在妨碍当前工作？
证据强度与收益分别表述，不用一个综合分掩盖高收益猜测。

合并需要新增转发层、例外配置、迁移机制或长期同步义务时，把这些成本算进去。
存在风险不自动否决变化，但移动了文件而未减少任何负担，不能算收益已经成立。

### 5. 先找能推翻清理判断的证据

对重要候选回答：它最有力的保留理由是什么？什么调用方、当前决定或历史教训会推翻删除建议？
确认失效与尚未发现用途分开。工具的未使用报告只是线索。
发现部分仍有效时收窄清理对象，避免“整个文件一起删”的粗粒度动作。

这不要求证明宇宙中不存在外部调用：在可知边界里建立依据，明确外部未知对行动的影响。

### 6. 用真实阅读或修改任务验收，并交代覆盖范围

整理前挑一个实际困难：例如确认当前配置优先级，或定位某项规则的唯一维护处。
整理后沿同一任务检查能否正确找到依据、理解例外和定位修改范围，同时保留行为回归检查。
还要回看合并后谁维护规则、其他消费者是否失去必要区别、仍有效的迁移目标是否被误作完成。
没有可比基线时只报告观察，不声称 skill 导致效率提升。

若用户要求多处或全仓整理，局部是推进批次，不能成为提前结束整个请求的理由。
用简短文字交代已看、未看和受阻范围即可，不额外建立评分系统或全仓关系数据库。

## 用户确认的上下文约束

用户指出上下文爆炸风险，并确认采用有界阅读、局部整理和按需回查。
正文已把它落实为阅读方法：每次展开对应一个待判断问题；外围依赖不自动扩大修改范围；
已有证据足够或新阅读不再改变判断时收束；缺证据时保留对象，不因上下文压力冒险删除。

任务已有工作记录承接进度、来源位置、未知与重开条件，按当前状态更新，不堆叠多轮摘要。
局部完成后后续表达只带结果和回查入口；环境不能清除历史上下文时，不声称已经释放它。
跨局部冲突或来源变化触发必要回查。委派按可独立回答的问题隔离，仅返回可核对的判断。

不设固定 token 门槛、文件数、读取轮次或强制 Agent 数。实际上下文开销与遗漏风险仍待现场验证。

## 下一步可用的验证场景（尚未执行）

找已有真实材料做小范围试用，允许得出无需修改；不为证明技能有效制造问题。

- 一个确认已失效的内部实现：应该清理实现与依赖残留，并保持有效路径。
- 一个无静态引用、但经注册或配置调用的入口：应该保留，说明使用依据。
- 两份覆盖同一概念、服务不同读者的文档：应该辨认视图关系，避免强制合并。
- 一份部分过时、仍包含当前约束或失败教训的设计：应该按内容拆分判断。
- 一段保留疑问或未验证条件的草稿/prompt：应该保留语义强度和行动边界。
- 一个跨代码、文档与配置的局部问题：观察是否只读取改变判断的关系，外围发现是否无故扩大范围。
- 完成局部后从工作记录恢复另一个问题：应能回查证据；来源已变或出现交界矛盾时重新核对。
- 用户指定多个局部的任务：应逐步完成约定范围，不把一次局部收束误当全任务完成。

独立评审者可在看作者整理结论前，尝试同一个真实阅读或修改定位任务，检查有无误删与理解损失。
这一步验证方法是否改变判断；不要求固定 Agent 数、操作顺序、轮次或成功率评分。
