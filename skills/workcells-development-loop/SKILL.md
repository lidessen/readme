# Workcells 开发闭环

分工是让不同关注点相互制约、校正并统一于用户目标，同时限制单次执行的上下文；并行是加速手段，不是完成依据。主协调者始终负责原目标、已确认约束、共享决定和最终整合。实现者可以自测，但不能仅凭自己的报告宣布目标通过；有实质风险或跨边界接线时，安排独立反证和真实验收。角色按需要组合，不为每项任务建立固定职位或审查轮数。

## 划界与委托

先读项目合同和当前状态，将目标拆到一个能走通真实入口、可独立验收的最小切片；不必一次拆完整项目。记录当前目标、验收条件、关键依赖、负责人、产物位置及待决问题。独立探索、反证和实现默认并发；强依赖先完成，任务到达即核对并释放下游，不等无关任务。为关键接缝和整体验收留出容量。并行可以接受适量重复探索，但不得无界递归派发或重复写入。

有共享接口时先明确唯一负责人和可引用的合同版本，写清必要的输入、输出、限制、错误行为及验证例子；双方按同一版本实现。允许交叉读取，明确各执行者写入归属，共享文件由一个负责人修改或在实际支持的隔离副本中整合。接口或全局前提变化时，通知受影响者确认新依据，不能直接合并基于不同版本的结果。这些写入归属是协作约定，除非环境提供实际隔离，不能宣称其为安全边界。

用 Task 作为持久主线，记录目标、验收、依赖、进度和阻塞；按需要使用子 Task、前置关系和当前 revision 的 CAS。短探索或审查可以直接 Delegate，但影响主线的决定与证据要关联回相应 Task。创建 Task 不派发；查看 ready 后显式 start。使用现场已验证的 CLI、Action 配置和项目权限，不虚构并行步骤或新调度能力。Action 执行配置中确定的步骤，主协调者负责选择任务、合流、解决争议、核对证据和决定是否完成；候选结果或 Run 成功不自动完成 Task，独立验收后才明确完成。选模型和额度遵循用户及环境的既有路由，不把执行适配器当业务调度器。

## 限定上下文，保留共同方向

为每次委托提供原目标与不可改变的约束、本次成果和范围、授权读写位置、当前合同版本、直接依赖和验收办法。按入口通过 Context 引用所需合同与证据；不要广播完整历史，也不要只给目录名。检查当前入口实际展开的字段；以支持的 contextRefs 或可读取且指定版本的合同路径传递合同，不假定 Task 的 inputRefs 自动注入。让实现者返回产物位置、改动、实际验证及结果、未决问题；反证者读取原目标、合同和实际产物，独立检查关键假设，不只复述实现者结论。

每次 cli-agent Run 都是新 session；前次 session ID 是审计线索，不作为恢复上下文的保证。必要信息以当前任务、引用和证据重新组装，区分必需内容与可选材料；检查权限、预算以及实际纳入或省略的记录。不要将密钥放入任务、普通 Resource 或模型上下文。

## 对立与统一

反证应针对原目标、已确认约束或可复现的失败，说明触发、证据和影响；新想法可以提出，但不自动升级为当前验收门槛。实现者发现合同缺陷时同样提出反例。争议由主协调者依据权威来源和证据裁决；若涉及用户未决定的目标或权限，反馈用户。影响共享接口的决定更新同一合同，再同步受影响方；不要让各 Agent 自建一套规则。

遇到失败先判断现有责任是否漏接、假设是否错误，或确实存在新的责任关系。修局部问题，不把每个失败升级为新架构、保障机制或固定门禁。已有设计在真实反例下不能解释必要行为时，再比较替代关系与代价。

## 整合、恢复和验收

尽早在合并后的结果上运行真实入口，核对关键接口和用户可观察行为；单元测试、模拟和真实运行分别报告。反证者或独立验收者对照原目标检查实际产物及证据；主协调者解决缺口，必要时只重开受影响部分和下游验证。阶段完成不等于整体完成；只有原范围与真实验收均满足，才明确完成目标。实际环境或权限受阻时报告已完成、确切缺口及下一步。

Run 的失败、超时或 unknown 不能证明文件未写入，也不代表产物全废；非零退出不保证存在输出 Resource。先查看原 Run/Delegate 的诊断、工作区和实际效果。对于可能有副作用或效果不明的执行，保留幂等身份，核对记录与实际效果，再按现有可用操作决定如何继续，不盲目重放；不要假定 Delegate 有通用的 unknown 对账修复命令，Action 对账也不自动重放后续步骤。已知纯读取失败可按证据诊断和复查，不人为阻断独立工作。取消请求不证明副作用已撤销。

复盘只记录有助于改进的事实：从需求到真实验收的时间、依赖或审批等待、接口冲突及返工、真实验收结果，以及下一次应改变的一项做法；不以 Agent 数量、测试数量或子任务数量衡量成功。实践中发现问题时，优先修正具体责任和接线，凭证据迭代本方法。
