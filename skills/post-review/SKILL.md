# Post Review

## 内容仓库

本仓库同时维护技能和内容：短想法写在 `notes/`，文章和草稿写在 `blog/`。
这里的内容会公开，草稿和图片源码也可见；`_` 前缀只排除站点渲染，不是访问控制。
只写适合公开的内容，不把私人工作对话、原始输入或内部审校记录藏进 HTML 注释。
修改本仓库仍需当前任务具有写入授权，技能本身不授予目录权限。

## 目标

对 `blog/` 中的文章做语义保真的审校和表达修订。文章可能来自用户、AI 或两者混合；审校的重点不是判断作者归属，而是修正语言问题，并把不自然的 AI 表达拉回作者自己的、接近 `notes/` 的表达方式。`blog/` 同时包含公开文章和 draft。

默认直接修改目标 Markdown 文件，不在文章正文中加入审校报告，也不另建审校副本。用户可以通过 Git diff 查看修改。

## 触发方式与范围

当用户使用 `/post-review <文件>`，或明确要求审校、修订、去除文章的 AI 味时使用本 skill。

- 目标必须是 `blog/` 下的一个或多个 Markdown 文件。
- 没有明确目标文件时，先根据用户上下文定位；仍然不明确时询问文件，不要默认审校整个目录。
- 只修改文章内容和确有必要的 Markdown 排版；保留 front matter、链接、代码、引用、图片路径和技术标识符。

## Draft 规则

- 文件名（basename）以 `_` 开头的 Markdown 文件是 draft，例如 `blog/_future-post.md`。
- draft 不进入站点公开文章列表或渲染；本仓库公开，草稿源码仍可读取，它可以在用户明确指定时被审校。
- 审校 draft 时保留 `_` 前缀，不改名、不移动到公开位置，也不把它当成已发布文章。
- 没有用户明确要求时，不对 draft 做“发布准备完成”的表述；完成后的回复要注明它仍是 draft。

## 风格样本：`notes/`

审校前读取 `notes/` 中已有的短想法，优先选择内容相关或较新的样本。只观察可见正文中的表达习惯：

- 句子长短和节奏
- 是否使用第一人称
- 直接程度、口语程度和抽象程度
- 对不确定性、限定词和判断的表达方式
- 常用词、转折方式和段落密度

不要把 `notes/` 中的事实、观点、例子或结论带入文章；不要照抄其中的句子，也不要为了“统一风格”抹掉文章中有意的技术、文学或个人表达。若 `notes/` 没有可用样本，保持文章当前能确认的作者语气，不臆造风格。

## 工作流程

### 1. 先理解再修改

通读目标文章，确认它的中心论点、叙述顺序、语气、证据边界和明确的不确定性。若文章存在用户明确标记的 AI 段落，重点处理这些段落；若没有来源标记，不用文本特征武断区分人写和 AI 写，按全文的实际表达问题处理。先确认目标是否为 `_` 开头的 draft，并在后续回复中保留这个状态。

### 2. 语义保真的修正

先做基础审校：

- 修正错别字、标点、语法、搭配、指代不明和明显的句子断裂。
- 只在关系可以直接确认时调整句序、连接词或段落衔接。
- 保留原文的主张、立场、语气、事实、证据范围、引用和不确定性。
- 发现疑似事实错误、论证缺口或无法判断的指代时，不擅自替作者下结论；保留原意并在回复中指出。

### 3. AI 表达的人性化处理

在不改变语义的前提下，对 AI 或混合来源中显得不自然的表达做风格化修订：

- 把冷僻、书面腔或为了压缩 token 而选择的少见词，换成该语言中更常见、更顺口的说法。
- 把过度压缩的名词堆叠、抽象套话和缺少主语的句子，改成清楚的动词和具体主语。
- 删除没有信息量的过渡、重复总结、模板化开场和机械收束。
- 拆开过长的并列句，恢复自然的句子节奏；必要时合并过碎但含义相同的句子。
- 减少不必要的对称排比、层层递进、咨询报告腔和“面面俱到”的罗列，让文章保留真实写作者会有的取舍。
- 参考 `notes/` 中的直接、自然和有个人痕迹的表达，但不强行口语化，不抹平专业术语，也不把所有句子改成同一种节奏。

不要建立固定禁用词表，也不要因为某个词“像 AI”就机械替换；判断依据是上下文中的自然度、作者风格和语义准确性。

### 4. 修改后的复核

完成后重新阅读修改处及其前后段落，确认：

- 核心意思、立场、事实和不确定性没有漂移。
- 没有把推测改成事实，把问题改成结论，把弱断言改成强断言。
- 没有引入 `notes/` 中的新信息，也没有丢失必要的限定、例子或引用。
- Markdown 结构、front matter、链接、代码和技术标识符仍然有效。
- 正文中没有留下审校过程、AI 来源说明或内部工作笔记。
- draft 仍保留 `_` 前缀，未被误当作公开文章。

## 边界

- 本 skill 是审校和表达修订，不是事实查证、重新论证、扩写文章或重写作者观点。
- “修正”以语言和明确的表达问题为主；无法确认语义时宁可保留并提示，不做自信的改写。
- “去 AI 味”不是把文章改成统一的标准文风，而是去掉不必要的冷僻、压缩和模板化表达，恢复作者自己的可读性。
- 不自动把 `notes/` 的短想法升级成 `blog/`，也不改变文件位置。
- 不自动发布、重命名或移除 draft 标记。

## 完成后的回复

简短告知修改了哪些类型的问题，例如“修正了语病，并将几处冷僻表达改为更自然的说法”。如有无法安全判断的语义、事实或来源问题，单独列出；不要重复整篇文章。
