# Draft Routing

在写入前确定唯一目标。路由的目标是维护文章边界，不是追求“总能命中一个旧 draft”。

## 显式路由

以下输入都视为用户已经指定目标：

- `/draft 01 <内容>`、`/draft #01 <内容>`
- 明确说“放进 01”“追加到 02”
- 给出 `blog/_01-*.md` 一类具体路径

编号匹配 basename 中 `_` 后的连续数字。编号存在时直接使用对应文件，即使标题后来改变。若该编号尚未使用，以该编号新建；若同一编号意外对应多个文件，停止写入并请用户确认，不能猜测。

明确路径必须位于 `blog/`，且 basename 以 `_` 开头。不要通过编号顺手重命名、移动或重新排序已有文件。

## 智能路由

没有编号或路径时，读取候选 draft 的 `title`、`intent`、`tags`、标题结构和可见正文，判断新材料是否延续同一个中心问题或文章意图。

一个清晰匹配通常同时满足：

- 新材料回答、扩展、质疑或举例说明该 draft 正在处理的同一问题。
- 能指出它在现有结构中的自然位置，而不需要先发明新的中心论点。
- 与其他候选相比有明确优势；共享 `AI`、`写作` 等宽泛主题词本身不构成匹配。

如果恰好有一个清晰匹配，追加到它。以下情况新建下一编号：

- 没有候选处理同一个中心问题。
- 两个以上候选同样合理，无法确认用户想延续哪一篇。
- 只有依靠大量扩写或改变某篇 draft 的文章意图才能容纳新材料。

新编号取现有编号最大值加一，至少两位，例如 `01`、`02`、`10`；不复用被删除或空缺的旧编号。没有编号的旧 draft 可以参与内容匹配，但不要自动给它改名或补编号。

## 多个想法

先判断输入中是否包含彼此可以独立成立、服务不同文章的问题。显式指定目标时尊重用户选择，把它们分别安放在同一 draft 中；自动路由时逐条判断，允许一次输入产生多个路由结果或新 draft。

路由完成后，在回复中公开实际选择及依据；不要把智能路由描述成确定无误的主题分类。
