# Draft

## 内容仓库

本仓库同时维护技能和内容：短想法写在 `notes/`，文章草稿写在 `blog/`。
这里的内容会公开，草稿和图片源码也可见；`_` 前缀只排除站点渲染，不是访问控制。
只写适合公开的内容，不把私人工作对话、原始输入或内部审校记录藏进 HTML 注释。
修改本仓库仍需当前任务具有写入授权，技能本身不授予目录权限。

## 目标

把用户间断提供的想法持续整理进 `blog/` 下同一篇 draft。允许多篇 draft 并存，用稳定的 `01`、`02` 编号定位；没有明确编号时，根据内容选择最相关的 draft。只做让新旧内容能够一起阅读所需的轻量文字处理和结构整理，不把零散材料擅自补成完整文章。

## 使用方式

显式指定 draft：

```text
/draft 01 新想到的一段内容
```

根据内容自动选择：

```text
/draft 新想到的一段内容
```

用户也可以直接给出 `blog/` 下的 draft 路径。命令或路径之后的内容都是本次要整理的材料。

## 工作流

### 选择 Draft

1. 只处理 `blog/` 下 basename 以 `_` 开头的 Markdown 或 MDX 文件。draft 始终保持 `_` 前缀，不进入站点页面和列表，不自动发布；本仓库公开，草稿源码仍可读取。
2. 枚举现有 draft。用户给出编号或路径时按其指向处理；没有明确目标时，先读取 [routing.md](references/routing.md)，再根据文章意图和内容选择目标。不要只凭一个相同关键词路由。
3. 如果没有唯一且清晰的匹配，新建下一编号的 draft，而不是把材料勉强塞进一篇不相关的文章。编号至少使用两位，从 `01` 开始，只增不复用。

一条输入中若包含多个明显独立的想法：显式指定编号时仍整理到该 draft 的不同位置；自动路由时分别判断，它们可以进入不同 draft。

### 整理与写入

4. 通读目标 draft，确认它当前的中心问题、已有结构、重复内容和未解决的矛盾。然后读取 [integration.md](references/integration.md)，把新材料放到语义上最合适的位置。
5. 修正新材料中的明显错别字、标点、断句和对话填充；可以合并重复内容、调整相邻段落或建立必要的小节，但保留原意、语气、限定和不确定性。
6. 保留现有 Frontmatter、链接、代码、引用和图片。更新 `updated_at`；新建 draft 时同时写入 `created_at`，并生成帮助后续路由的简短 `intent` 与少量 `tags`。
7. 写入后重读修改处及其上下文，确认没有制造新论点、虚构连接、解决原本未解决的矛盾，或把 draft 写成貌似完成的文章。

## 新建 Draft

文件名使用稳定编号和简短 slug：

```text
blog/_01-short-slug.md
blog/_02-another-topic.md
```

新文件使用以下最小结构：

```markdown
---
title: 暂定标题
draft_id: "01"
intent: 一句话说明这篇文章正在探索的问题或判断
created_at: YYYY-MM-DDTHH:mm:ss+08:00
updated_at: YYYY-MM-DDTHH:mm:ss+08:00
tags:
  - 主题
---

# 暂定标题

整理后的第一段材料。
```

标题、`intent` 和标签都可以随着文章方向逐渐清晰而调整，但不能为了显得完整而引入用户没有表达过的主题。编号一旦分配，不随标题变化而改变。

## 边界

- 这是积累和整理 draft 的 skill，不是文章代写、深度扩写、事实查证、最终审校或发布流程。
- 显式编号优先于智能路由。智能路由只能选择或新建 draft，不能自动合并、拆分、重命名或发布已有 draft。
- 结构整理服务于容纳真实材料；不要补写论据、例子、结论、转场或“升华”来填满结构。
- 无法安全安放的内容可以保留在暂存小节，不要丢弃，也不要强行解释。

## 完成后的回复

说明材料被路由到哪个编号和文件、是新建还是追加、放进了哪个小节，以及做过哪些轻量整理。若自动新建、存在明显冲突或仍有未安放内容，要明确指出。始终注明文件仍是 draft。
