# Post Visual

## 内容仓库

本仓库同时维护技能和内容：短想法写在 `notes/`，文章和草稿写在 `blog/`。
这里的内容会公开，草稿和图片源码也可见；`_` 前缀只排除站点渲染，不是访问控制。
只写适合公开的内容，不把私人工作对话、原始输入或内部审校记录藏进 HTML 注释。
修改本仓库仍需当前任务具有写入授权，技能本身不授予目录权限。

## 目标

为 `blog/` 中的文章创建配图或封面，并把视觉资产以可追溯、可维护的方式放回文章项目。视觉不是文章的装饰性附属物：配图要完成明确任务，封面可以弱关联，但要有足够的美观、吸引力和独立记忆点。

## 触发方式与范围

当用户要求“给文章配图”“创建封面”“生成插画”，或使用 `/post-visual <文章>` 时使用本 skill。

- 目标是 `blog/` 下的一篇文章或一个明确的文章主题。
- 如果没有明确目标，先定位文章和视觉用途；不要为整个博客批量生成图片。
- 可以创建图片、选择变体、保存资产并在用户需要时把图片链接插入文章；不要借机改写文章正文。

## 公开文章与 draft

- `blog/` 中 basename 以 `_` 开头的文件是 draft，例如 `blog/_future-post.md`，不公开展示或渲染。
- draft 可以明确指定后生成视觉草稿，但不把它当成公开资产，不移除 `_` 前缀，也不自动发布。
- 公开文章的资产放在 `blog/assets/posts/<post-slug>/`，构建输出到 `/assets/posts/<post-slug>/`；draft 的资产放在 `blog/assets/posts/_<draft-slug>/`。本仓库的站点构建会把 `blog/assets` 复制到内容树的 `assets/`，所以 URL 是 `/assets/posts/...`，不是 `/posts/assets/...`。构建会排除路径任一部分以 `_` 开头的资产，不把草稿图片当作公开 URL；仓库本身是否公开是另一个边界。
- 文章与图片都要保留稳定、清楚的命名，例如 `cover.webp`、`figure-01.webp`；不使用含义不明的随机文件名作为最终资产名。

## 参考与审美方向

使用 [aesthetic-preferences.md](references/aesthetic-preferences.md) 和 references 根目录中现有的工作坊图片作为本博客的审美偏好参考。先理解参考图中可迁移的关系，再为当前文章重新设计；不要照抄具体画面。

可以优先探索：

- 插画、手绘、涂鸦、纸张、木材、铅笔或印刷质感
- 温暖、克制但有记忆点的色彩
- 几何结构与自然形态、工作台或制作痕迹的结合
- 清晰的黑色线条、手绘轮廓、局部亮色和有识别度的插画形体
- 有留白、有构图节奏、缩略图下仍然醒目的画面

这些是偏好方向，不是每张图都必须具备的固定风格。根据文章和用途保留、改变或拒绝它们。

## 工作流程

### 1. 定义视觉任务

先用一句话说明图片要做什么：

- **配图**：关联文章中的一个具体概念、例子、场景、情绪或阅读节点；关联性和信息作用优先于单纯漂亮。
- **封面**：为文章建立第一印象和视觉吸引力；可以只关联主题的气氛、隐喻或材料，不强求 literal illustration，也不强求把文章摘要画出来。

如果同一请求同时需要配图和封面，分别定义任务，不用一张图同时承担两个冲突目标。

### 2. 形成图像方向

根据文章的语气、目标读者、图片用途和版面比例，确定媒介、构图、主体、色彩、质感、光线、留白和裁切安全区。封面尤其要考虑缩略图和横向裁切下的识别度。

生成提示时使用具体的视觉关系和画面条件，不堆叠空泛的风格标签。除非用户明确要求，不在图中加入标题、说明文字、logo 或难以控制的排版；文字应由网页或文章层处理。

### 3. 生成或选择

使用可用的图像生成能力生成新图；如果已有候选图，先比较它们是否完成了定义的视觉任务，再选择或提出最小修改。需要选择时可以提供少量有明显差异的变体，不为了“多几个选项”而无目的堆图。

### 4. 视觉复核

检查实际图像，而不是只检查提示词：

- 配图是否真的帮助读者理解、停留或转场，而不是重复正文。
- 封面是否好看、醒目、有吸引力，并且在弱关联下仍不显得随意或空洞。
- 插画/手绘/涂鸦质感是否自然，是否沦为表面滤镜。
- 主体、对比度、留白和安全区是否适合文章位置、缩略图和移动端。
- 是否出现错误文字、奇怪结构、无意的品牌元素、版权风险或与文章不符的具体事实。

不因“风格像参考图”就接受结果；任务完成度和画面质量优先。

### 5. 保存与挂接

将最终资产保存到对应文章的 `blog/assets/posts/` 路径，使用稳定命名，并为插图准备准确、简洁的 alt 文本。只有在文章渲染器支持相应方式时才更新 cover front matter；否则使用文章中的 Markdown 图片引用，或先只保存资产并说明尚未接入渲染。

对于 draft，保留 draft 路径和状态，不把图片链接暴露为公开文章资源。对于公开文章，插入链接前检查相对路径、文件扩展名和目标文件位置。

## 边界

- 配图和封面是不同的视觉任务：配图要有目的，封面可以弱关联但不能无审美判断地随机配图。
- 不复制归档参考图的具体构图、对象、角色、文字或整套表面风格；只借鉴审美关系。
- 不默认沿用参考图中的女性角色、漫画角色或 logo 语汇；它们只是可选择的视觉材料。
- 不把参考图当作可自由复用的公共素材、外部授权或项目已经接受的统一视觉规范。
- 不为了生成图片而改变文章语义、事实、结构或作者风格。
- 不自动为 draft 公开渲染，也不因生成了视觉资产而把文章标记为完成或发布。

## 完成后的回复

说明生成或选定的是配图还是封面、它服务的视觉任务、保存路径以及是否已经挂接到文章。若有未解决的裁切、渲染、授权或视觉判断问题，明确列出，不把“文件已生成”当成最终发布验证。
