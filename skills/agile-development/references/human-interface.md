# 和人交流：决策点、上下文与授权

这份参考解决一个接口问题：Agent 掌握的执行上下文远多于人，而人仍是当前不可缺的
决策者。交流的目标不是把所有信息同步给人，而是让人在有限注意力下做出高质量决定；
信息透明服务于这个目标，不是目标本身。

默认预算：每次交流 2–3 个决策点；需要认真读的部分约 500 字以内。它是实验起点，
不是硬门禁；按项目、渠道和人调整。

## 先分清楚：汇报、决策、授权内行动

| 类型 | 人要做什么 | 怎么给 |
| --- | --- | --- |
| 状态汇报 | 知道即可 | 结论 + 证据链接；不要求确认 |
| 决策请求 | 选择、裁决或授权 | 2–3 个自足决策点；明确时间和默认 |
| 授权内行动 | 不需要动作 | 直接做，记录假设；交付时说明。本地提交、分支和可逆检查点属于这一类 |

不要在状态汇报里夹带需要人决定的事，也不要把已经授权的事再问一遍。需要人决定时，
第一句就说“需要你定什么”。

## 决策点的来源

不是每个实现选择都要上升给人。通常需要人介入的是：

- 硬边界：权限、支付、迁移、事务、外部合同、密钥、不可逆副作用。
- 目标和优先级：任务与项目定位/战略冲突，主线切换，范围变化。
- 公开契约：API、schema、协议、兼容性承诺。
- 风险接受：`R2` 否决、无法回滚、需要人类 owner 签字。
- 缺少授权：项目规范没有覆盖，或超出本次任务授权。

技术默认、可逆选择、实现细节、已有验收覆盖内的取舍，默认由 Agent 决定并记录假设。
任务内的本地提交、分支、worktree 和可逆检查点也默认由执行者完成，不作为人的决策点；
项目规范或任务明确要求提交前确认的除外。需要人的是推送/公开、发布、不可逆、跨项目和
超出授权。拿不准是否在授权内时，走可逆路径并标注待确认，不要用请示代替判断；硬边界
例外，必须先问。

## 一个决策点的结构

每个决策点应该能独立阅读，不依赖前文：

1. **要定什么**：一句话，具体到选择和后果。
2. **为什么现在定**：不定的阻塞点、时间窗口或风险。
3. **上下文**：1–2 句必要背景；宁可重复，也不要求人回忆前文。
4. **选项**：2–3 个，每个写后果、成本、风险和可逆性；不要只列术语。
5. **建议**：推荐哪个，理由是什么。
6. **不定的后果**：默认走哪条、能否晚点定、最晚什么时候定。
7. **决定之后**：谁执行、下一步是什么、什么时候回报。

选项超过 3 个时，先合并或先按默认值排除，不要把选择题变成阅读理解。没有明显推荐
时，说明缺哪条证据，以及准备怎么补。

## 自足性检查

发给人之前，把这条消息单独拿出来，假设对方没看过来源会话的原文、日志或上一轮对话：

- 能否在 500 字内知道发生了什么、要定什么？
- 每个选项是否用完整说法写清做什么、代价和后果，而不是只写 A/B、方案一/二？
- 不选时的默认动作是什么，最晚什么时候定？
- 对方是否需要问“A 是什么”“哪个文件”“上次那个方案”才能回答？

如果对方会问这类问题，这条消息就不合格。选项标签只在原始上下文里有意义；转述时必须
重新展开，不能把来源会话或子 Agent 的 A/B 直接搬给人。

## 示例

```md
需要你定：这次回归的 receipt 缺失是否阻塞发布？

背景：业务成立 5/5，首见 3/5；两次缺失都伴随重放，没有错误动作。
选项：
A. 按现通过线发布，把首见作为诊断项（今天可发）。
B. 先修 receipt 再发，预计多花 1–2 天，可能错过本周窗口。
建议：A。现通过线不含首见，且没有错误动作；修复排进下一批。
不定：默认 A，明天 10:00 前没有回复就按 A 执行。
```

这段需要认真读的部分约 200 字；原始回执、日志和失败归因放在链接里，人不需要先读。

## 上下文：必要冗余，不倾倒

- 每个决策点自带最小充分上下文；重复关键数字、路径、前提是允许的，避免人翻前文。
- 详细证据放链接、附录、批次目录或文档；正文只留做决定所需的部分。
- 用具体路径、命令、数字和结果，不用“那个文件”“上次说的方案”。
- 不要求人读完整 diff、完整日志或全部对话才能做一个决定；需要时给出摘要和关键位置。
- 背景可以放在决策点之后，或折叠到“需要时展开”；先给结论和选择。
- 多个决策点按重要性排序；一次只给一组，不要把所有待定事项打包。

## 超过预算怎么办

- 先用授权、默认值和可逆路径解决能解决的，只把真正需要人的留下。
- 超过 3 个决策点时，拆成多次交流，或按主题分批；不要合并成一份长文。
- 单个决策点超过 500 字仍说不清，通常是任务没定形：先补证据、缩范围或拆任务，再把
  选择交给人。
- 人要求更多背景时，给链接和摘要，不复制全部上下文；人明确要读全文时再给。
- 人没有回复时，在授权内继续可逆工作；硬边界停住，留下决策包和默认动作，不擅自越界。

## 对子 Agent 的交流

同样的原则适用于 Agent 之间，只是预算可以更宽：

- 交代目标、为什么、边界、验收和决定权，不只给步骤。
- 要求子 Agent 按“结论 → 证据 → 需要上级决定的事”汇报，不倾倒工具日志。
- 子 Agent 需要人决定时，先报给主 Agent；主 Agent 汇总成 2–3 个决策点，不让每个
  worker 直接打断人。
- 主 Agent 的决策包要保留子 Agent 的证据链接，方便人追问。

## 授权与记录

- 授权内：直接做，记录假设、影响和回滚方式；交付时说明，不逐步请示。
- 授权外：带证据提出选项，等人决定；不沉默执行，也不擅自扩大范围。
- 可逆的小改进可以先做后报，但要标明是假设，并给出回退点；硬边界、不可逆操作、
  目标变化不适用。
- 人的决定写进现有决策记录或任务载体；后续执行按决定走，不反复确认，除非出现新证据。
- 决定被新证据推翻时，带新证据重新开一个决策点，说明为什么之前结论不再成立。

## 实验与调整

先按 2–3 个决策点、约 500 字运行几轮，观察：

- 人是否要求补充背景，或误解决策点。
- 从发出到决定的时间，以及决定后返工次数。
- 人是否把授权内的事退回，或对越界决定提出异议。
- 决策点是否经常超过 3 个，说明任务定形或授权边界有问题。

根据观察调整预算和格式；不要用字数考核，也不要把预算变成阻塞开发的 gate。交流质量
看决定是否正确、及时、可执行，不看消息长短。

## 反模式

- 上下文倾倒：把日志、diff、分析全文贴给人，让人自己找重点。
- 决策夹带：在长汇报末尾藏一个需要人拍板的问题。
- 审批表演：授权内的事反复请示，或为了留痕制造不必要的确认；把本地提交、分支或可逆
  检查点当成人的决策点，让开发停下来等审批。
- 虚假紧急：没有时间窗口却催人立刻决定。
- 选项过载：一次给五个以上选项，或只给术语不给后果。
- 指代前文：让人看“上面第 3 项”“之前那个文件”。
- 只给 A/B 或方案编号，不写选项内容；标签只在原始上下文里有意义，转述时必须重新展开。
- 只报状态，不说需要什么；或只给建议，不说选项和后果。
- 硬边界先斩后奏，或目标变了不告诉人。
- 让每个子 Agent 直接找人，绕过主 Agent 汇总。

## 完成条件

- 每次需要人的交流不超过 3 个决策点；每个决策点自足，有选项、后果、建议和默认。
- 需要认真读的部分在约定预算内；详细证据可展开，不占主阅读路径。
- 没有把决定藏在状态汇报里，也没有在授权内反复请示。
- 硬边界、目标冲突、范围变化和 `R2` 否决已经升级给人。
- 人的决定已记录，并反映到下一步行动；新证据出现时才重新打开。
