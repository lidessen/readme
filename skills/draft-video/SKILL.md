# Draft Video · 在便宜阶段迭代

演示和讲解视频先验证要讲什么、怎样讲，再逐步增加画面和声音的制作成本。高频修改放在
脚本和分镜阶段；每个镜头独立制作、验收和返工，最后检查整片的节奏与声画接合。阶段是
反馈循环：发现问题就回到最便宜的有效修改处，再重做受影响的下游产物。

## 先对齐，再逐级增加成本

0. **目标与钩子。** 对齐目标、受众、时长和观众应记住的单一信息，以及开头如何吸引该
   受众。核对已有素材、发布规格、预算与可用工具；无法从上下文合理确定、会改变方向的
   决定交给用户。不要把暂定假设当成已确认事实。
1. **脚本与结构化分镜。** 写旁白与镜头顺序，用表格或 JSON brief 逐镜头记录 `shot_id`、
   `duration`、`narration`、`visual_intent`、`asset_type`、`transition`，并说明时长单位。
   在这里先反复调整叙事结构、信息密度、节奏和总时长；明确每镜头要展示什么及验收条件。
   审查信息是否服务目标、画面是否能承载旁白、时长是否可读可讲；通过后才制作草图。
2. **粗分镜草图。** 用线框、草稿帧或可用的本地、低成本图像生成工具（例如 image-use 类
   工作流）逐镜头验证构图、文字可读性和画面流动，不追求精细质感。比较相邻镜头与脚本，
   构图和视觉衔接通过后才制作精图；不通过就修改草图或回到分镜。
3. **最终关键帧精图。** 逐镜头完成并锁定构图、视觉风格、素材与关键文字；确认它们符合
   对应分镜和验收条件，且跨镜头一致。精图通过后才进入昂贵的视频生成；变更需重新检查
   受影响镜头及其依赖。
4. **镜头片段。** 按锁定关键帧和镜头 brief 独立生成或渲染片段。讲解和软件演示优先考虑
   video-as-code：借鉴 motion-use、HyperFrames 的 JSON brief 或“帧是时间的函数”模式，
   以可编辑参数控制界面、文字、动画与时长；只在确有需要时使用生成式视频片段。工具和
   能力以实际环境为准，不假定这些示例已安装。逐镜头检查内容、运动、时长和过渡。
5. **声音、合成与验证。** 制作旁白，调整旁白与镜头的入点、停顿和时长，再混音、封装
   输出。按交付平台或项目规格确定响度目标（例如集成响度 -14.5 LUFS），测量并检查
   削波；抽查开头、结尾、关键帧和转场，程序化核对片段/旁白时序、总时长、音视频轨道
   及封装是否符合规格，并播放成片检查同步、可读性与节奏。工具不可用或未实际播放时，
   如实标记未验证项。

每道关口由实际接受者审查当前产物；未通过时不进入下一道更昂贵的制作。用户已给出明确
方向时可自主完成低风险细节，最终接受权仍归用户；需要其选择的方向未确定时停在低成本
阶段，不把草稿当作批准。

## 方向不明时先比较候选

用户尚不确定风格、语气或结构时，在阶段 1 或 2 按需求复杂度与待比较方向探索少量有明显
差异的低成本候选，不预设固定数量；让候选在叙事角度、节奏或视觉风格上形成可辨别的取舍，
而非只换颜色或措辞。用简短比较表呈现
每个候选的方向、适合的受众/目标、取舍和相对制作成本；成本是基于当前工具与素材的估计，
未知就标明。让用户选择、淘汰或组合，再按反馈迭代直至方向收敛，之后才制作精图或片段。

## 分镜头交付与局部返工

每个 `shot_id` 是独立交付单元：保留其 brief、验收条件、锁定关键帧、素材及可重建的片段
或渲染参数；记录版本及与相邻镜头、旁白的依赖。验收至少覆盖信息、画面、时长和衔接。
修改时定位受影响镜头，回到该镜头最便宜的有效阶段，只重做变化的镜头及最终合成，并
复核受影响的旁白时序和相邻接缝；不重新生成整片。若整体方向或共享素材改变，先确定
实际受影响的镜头范围，再逐一处理，保留未受影响的产物。

交付时给出成片和可继续编辑的素材或参数位置，说明各阶段接受状态、实际执行的时序、
响度与播放检查，以及未验证的内容；制作观察不等于观众效果已获验证。
