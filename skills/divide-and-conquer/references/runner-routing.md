# 执行器与模型选路

在多个执行器、模型或订阅通道间委派工作时，先按能力与隔离门槛选路，再按计费边界与
配额紧迫度权衡，并在单个任务内保持稳定。选路只服务当前任务，不形成固定厂商榜单或
永久默认。

## 能力与隔离门槛优先于低价

- 按任务类别、工具调用可靠性、所需上下文、工作目录隔离与会话恢复能力筛选候选。
- 区分执行终端的位置标识与执行器自身可恢复的 session ID；前者不代表可续接会话。
- 不满足能力门槛的通道即使免费也不入选；长任务先确认恢复路径与失败后的对账方式。

## 粗粒度选路与缓存保护

- 选路只在任务或子任务开始，或当前通道额度耗尽、持续限流需要切换时触发一次。
- 单轮任务内保持选定模型与执行器，以保护 Prompt Cache 与推理连续性。
- 不为每个子步骤频繁切换模型；确需切换时按一次显式通道变更记录原因与影响范围。

## 计费边界、共享池与临期配额

- 区分原生订阅、共享配额池与按量计费 API；同一共享池的多条路由不算多份余额。
- 结合固定窗口重置时间、套餐到期与手动重置券到期的紧迫度，优先消耗临期合规额度。
- 未获明确授权时绝不静默溢出到额外扣费通道；无法核实收费边界时按阻塞处理。

## 限流、耗尽与未知效果分类

- 遇到 `429` 或失败先按回执与 `Retry-After` 区分短期限流、并发上限、窗口耗尽与
  认证/计费错误。
- 切换备用通道时优先保持同能力档位，避免降级后重做；余额未知既不是零也不是无限。
- 请求已发出但结果 `unknown` 时先核对现场与产物对账，严禁盲目重放导致双重写入。
- 付费 fallback 未获授权时，等待重置、改用已核实候选或返回阻塞。

## 记录与复核

- 记录实际 route（执行器、provider、模型准确版本与推理档）、选择理由、查证日期及
  已知的共享池与用量限制。
- 模型、套餐条款、目录或任务类型变化，证据过时或反复失败时，只刷新受影响的判断。
