# Worker 与 Advisor：高劳动执行与高价值拍板

复杂任务里有两类性质不同的贡献：高劳动的收集、低级加工、成文与执行，和高价值、低劳动的
思路、方向与边界判断。把这两类贡献分给 Worker 模型（高劳动执行者）和 Advisor 模型（高价值
方向与边界把关者），由谁承担取决于当前能力与成本，不预设固定层级；同一 Agent 也可以在不同
阶段换位承担，但一次委托内职责必须分清。

## 职责切分

- **Worker（高劳动：收集、低级加工、成文与执行）**：收集资料，读代码与日志，把原始现场
  压缩成干净事实（已知、未知、矛盾、证据位置）供决策；严格依据已定思路和边界写文档、
  写清楚实现细节、编码测试并推进执行。
- **Advisor（高价值、低劳动的思维活动）**：消费加工后的干净事实，给出设计思路、把握方向、
  设定边界、裁决关键取舍；不必耗费成本一次性写出事无巨细的成熟长文档，但每次输出必须把
  当前阶段的“怎么设计”钉死，使下游能直接展开。

分工看劳动与价值的性质，不看地位高低：事实收集与既定思路的展开交给 Worker，需要在新
分叉之间做取舍的判断留给 Advisor。

## 写清细节不等于完善设计

把已定思路展开成可执行细节，是 Worker 的正当劳动；替决策者补做未决设计，是越权。委托
不得把需要自行思考“怎么设计”的空白留给 Worker 猜测：选项未定、取舍未裁的内容，不能
伪装成“细节待补”下发。

Worker 遇到未覆盖的设计分叉、前提失效或原则冲突时，立刻停下，把新现场压缩成事实回传
Advisor；不擅自发明设计，也不用堆砌候选方案拖延。回传与拍板按需触发，轮数由新事实
决定，不设固定节奏。

## 按需多轮交替

复杂任务不是单向瀑布，而是按需多轮的交替闭环，直到收敛收口：

> Worker 收集与低级加工 → Advisor 定思路、方向与边界 → Worker 写文档、展开细节并推进
> 执行 → 遇新事实或分叉回传 Advisor 再定边界 → Worker 继续推进

每轮交接都压缩：Worker 交干净事实与执行进展，Advisor 交钉死的设计决定与边界。没有新
分叉时不重复请示；分叉真实存在时不硬凑方案继续写。

## 常见反模式

- 让高价值的 Advisor 承担海量读仓、写长文档等高劳动活，把成本花在不改变判断的地方。
- 只给 Worker 一个模糊方向就放手，让其边写边猜设计，把未决方案伪装成实现细节。
- 遇到分叉硬凑一个方案继续推进，不回传、不拍板，方向错误积累到整合时才暴露。
- 没有新分叉也机械反复请示，把交替变成仪式，只消耗等待成本，不产生新的边界决定。
